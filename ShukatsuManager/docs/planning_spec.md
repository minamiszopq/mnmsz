# 就活選考管理アプリ 企画・仕様書

## 1. コンセプト

個人開発によるスマホアプリ。就活生向けの選考管理アプリ。
既存の「就活管理」「就活ノート」等の選考管理特化アプリはUI/UXが古く、
Notion・スプレッドシート等の汎用ツールはオフライン安定性やテンプレの手間に課題がある。

**差別化ポイント**
- オフラインでも安定して動作するローカル完結設計
- 既存の選考管理アプリより洗練されたUI/UX
- Notion等からの乗り換えを容易にする、任意タイミングでの非同期インポート/エクスポート

## 2. ターゲットユーザー

- 新卒就活生(全般)

## 3. 収益化の方向性

- 基本無料 + 付加価値機能の課金
- 就活は季節性が高いため、月額サブスクだけでなく単発課金(買い切り/シーズン課金)も検討

## 4. 技術方針

- クロスプラットフォーム: Flutter
- データ: 端末内ローカルDB完結
- 通知: ローカル通知(サーバー不要)
- 配布: iOS(App Store)/ Android(Google Play)両方

### 初期費用(概算)

Apple Developer Program：年間 $99
Google Play Developer：初回 $25

## 5. データモデル(企業レコード)

| フィールド | 型 | 備考 |
|---|---|---|
| 企業名 | 文字列(必須) | |
| 業界名 | 文字列 / タグ選択 | プルダウン候補を用意 |
| 選考状態 | 選択式(状態遷移) | 下記「選考状態の遷移」参照 |
| マイページID | 文字列 | |
| マイページURL | URL | タップでブラウザ起動、長押しでコピー |
| 締切・面接日時 | 日時 | 通知のトリガーに使用 |
| メモ | 自由記述(複数追加可・時系列ログ形式を想定) | ES本文・面接振り返り等 |

### 選考状態の遷移(要確定)

```
エントリー → 書類選考 → 一次面接 → 二次面接 → 最終面接 → 内定 / お祈り
```

※ 企業によって面接回数が異なるため、状態追加可能で、自由入力できる。

## 6. 画面構成

### 6.1 一覧画面(ホーム)
- ステータス別タブ/フィルタ(すべて / エントリー中 / 選考中 / 内定 / お祈り済み)
- 企業カード一覧(企業名・業界名・選考状態バッジ・次の締切日)
- 締切が近い(3日以内など)カードは強調表示
- 並び替え: 締切が近い順(デフォルト)/ 登録順 / 企業名順
- 新規登録への導線(フローティングボタン)

### 6.2 企業詳細画面
- 企業名・業界名・選考状態(変更可能)
- マイページID / URL
- 締切・面接日時 + リマインド設定
- メモ欄(時系列ログ)
- 編集・削除ボタン

### 6.3 新規登録/編集画面
- 必須項目: 企業名
- 任意項目: 業界名、選考状態(初期値: エントリー)、マイページID/URL、締切・面接日時、メモ

### 6.4 設定・データ管理画面
- 通知ON/OFF、リマインドタイミング設定
- CSVエクスポート/インポート
- テーマ(ライト/ダーク)
- Notion連携ボタン

## 7. MVP機能スコープ

**含む**
- 企業CRUD(登録・編集・削除・一覧)
- ステータス別フィルタ・ソート
- 締切・面接リマインド通知(ローカル通知)
- CSVインポート/エクスポート

**含まない**
- クラウド同期
- Notion連携(任意タイミングの非同期インポート/エクスポートとして将来追加)
- AI添削
- 選考体験談データベース
- 企業情報の自動取得

## 9. 検証プロセス(参考: Lean Startupの基本サイクル)

1. Problem Validation(課題検証): 就活経験者へのヒアリング、SNSでの需要確認
2. MVP開発: 上記スコープに基づき実装
3. Soft Launch: 少人数の初期ユーザー(Early Adopters)へ提供、フィードバック収集
4. Monetization: フィードバックを反映し有料機能を導入
5. 継続改善: Churn Rate / Activation Rate / Retention を見ながら改善・拡張
